## Known Limitations

- [ ] PyProver bridge `verify()` returns a structurally-correct placeholder until a real PyProver invocation is wired in (PyProver package not installed in this environment)
- [ ] Static analysis tools (Phase 0, Python) require mypy, pylint, bandit installed
- [ ] Z3 solver requires z3-solver package
- [ ] Rust-Debug requires rustc + clippy installed
- [ ] Cpp-Debug requires clang/clang++ installed
- [ ] GitHub analysis requires public repository access
- [ ] Async tracking via context managers (not true async execution)
- [x] ~~Phases 5-10 (C/C++ DWARF/KLEE, Assembly disassembly/dataflow/angr) not yet implemented~~ - STALE, fixed v2.5.0/v2.6.0: all of Phases 5-10 are implemented and tested (DWARF, CBMC/KLEE, strace, valgrind, Capstone disassembly/CFG, taint dataflow, angr). See CHANGELOG.md.
- [ ] KLEE has no prebuilt binaries on any platform/package manager checked (pip, apt, GitHub releases) - source-only, requires a patched LLVM + uclibc build. Not a suite bug; documented in roadmap.md §11.2.
- [ ] Three separate, mutually-incompatible `RiskLevel` enum classes exist in the codebase (`common.interop`, `master_debugger.types`, `master_debugger.orchestrator`) - `==` comparisons across them silently fail despite identical `repr()` output. Not fixed as of v2.6.0; see roadmap.md §11.6 for the full writeup and reproduction.
